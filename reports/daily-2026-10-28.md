## 1. elayadesign/ai-design-skills

**9,979⭐ · 今日 +1395 · —** · 创建于 2026-07-29 · [仓库](https://github.com/elayadesign/ai-design-skills)

**它到底是什么**：这是一个为 Claude Code、Cursor 等 AI 编码工具提供设计技能的集合库。它将“着陆页设计”等技能封装成独立的 Markdown 文件，用户只需将其复制到工具的配置目录，即可让 AI 按照预设的视觉系统（字体、间距、动效）生成专业的设计稿或代码。

**核心机制**：
- 模块化技能包：每个技能是一个独立文件夹，包含 SKILL.md 规则文件。
- 上下文注入：通过将规则文件复制到特定路径（如 .claude/skills），将设计约束注入 AI 的上下文窗口。
- 视觉系统定义：在 Markdown 底部定义设计变量（字体、颜色、间距），实现一处修改、全局生效。
- 跨工具适配：通过路径映射机制，适配 Claude Code、Cursor、Codex 等不同工具的规则加载协议。

**使用场景**：
- 快速原型开发：开发者需要快速搭建着陆页或落地页，但缺乏设计经验，利用该技能让 AI 生成结构完整、视觉统一的页面。
- 设计系统标准化：团队希望 AI 输出的代码或设计稿遵循统一的视觉规范（如特定的排版和圆角），通过修改配置文件即可实现。
- AI 编码工具进阶：Cursor 或 Claude Code 用户希望利用工具的“规则”功能，将设计思维转化为具体的工程约束。

**需要注意的坑**：
- 上下文窗口溢出：复杂的技能规则文件可能过长，导致 AI 在生成代码时截断关键指令，影响设计还原度。
- 工具路径变动：AI 编码工具的规则加载路径可能随版本更新而改变，导致配置失效。
- AI 理解偏差：AI 可能会忽略某些设计约束，特别是在处理复杂交互或非标准布局时，需要人工复核。

**核心机制**：

**使用场景**：
- 开发者使用 AI 工具快速生成网页原型，但担心设计看起来很“假”或缺乏质感。
- 需要为特定业务（如预订、商店、API 文档）生成具有特定主题（如 Dusk、Cobalt）的页面。
- 需要对现有网站进行重设计，同时保留原有的内容和功能结构。
- 需要审计现有网页，检查其是否包含典型的 AI 生成缺陷。

**需要注意的坑**：
- 环境依赖：需要 Node.js 18+、全局安装 Puppeteer 和 Chrome 才能运行浏览器检查功能。
- 工具绑定：它是特定 AI 编程工具的“技能”，不是通用 CLI 工具，需要通过 `npx skills add` 等特定命令安装。
- 照片许可：虽然引用了 Wikimedia Commons 的照片，但每个照片都有独立的 CC 许可证，使用时需注意合规。
- 复杂度：对于简单的静态页面，引入这套复杂的检查和渲染流程可能显得大材小用。

## 3. nightly-labs/openbot

**2,680⭐ · 今日 +777 · TypeScript** · 创建于 2026-08-12 · [仓库](https://github.com/nightly-labs/openbot)

**它到底是什么**：这是一个本地优先的桌面工作空间，用于管理多个 AI 代理（如 Codex、Claude、Grok 等）。它为每个 AI 团队成员提供独立的会话、文件系统和浏览器控制权，支持代理间协作、任务队列、文件共享以及嵌入式浏览器操作。

**核心机制**：
- 通过 OpenAI 兼容接口和 ACP（Agent Communication Protocol）连接 Codex、Claude、Grok 等多种本地或远程模型。
- 每个 Agent 拥有独立的上下文窗口、对话历史和文件目录，确保状态持久化。
- 集成了嵌入式浏览器，并通过 `cua-driver` 在桌面端实现类似 Computer Use 的自动化操作（读写文件、运行命令、控制 UI）。
- 支持 Agent 之间发送消息、反应、图片和文件，实现团队协作。
- 使用 FIFO 消息队列处理任务，支持暂停/恢复/取消，并利用 Electron 的沙箱机制隔离渲染进程。

**使用场景**：
- 开发者利用多个 AI 代理分工协作，一个负责写代码，一个负责测试，一个负责文档，通过共享工作空间进行开发。
- 需要同时管理 Codex、Claude 和 Cursor CLI 等多个工具，希望在一个统一界面下调度它们。
- 利用 Computer Use 功能，让 AI 代理通过浏览器自动登录系统、点击按钮、填写表单或执行命令。

**需要注意的坑**：
- 极高的安全风险：代理默认以 `danger-full-access` 权限运行，无需每次操作确认，可读写文件、运行命令、控制浏览器，必须完全信任代理。
- 非商业许可：采用 PolyForm Noncommercial 许可证，禁止商业使用，限制了企业级部署。
- Linux 远程桌面限制：Linux 版的远程桌面功能仅支持 X11，不支持 Wayland，且 arm64 版本可能缺少此功能。
- 开发预览状态：当前处于开发预览阶段，可能存在 Bug 或功能不稳定。

- 复杂项目开发：需要将大型需求拆解为可执行任务列表并自动推进的项目。

**核心机制**：
- 技能化命令架构：提供 24 个预定义命令，覆盖从设计规划到最终交付的全流程。
- 确定性规则检测：内置 62 条无需 API 调用或大模型推理的本地规则，用于检测并拦截常见的 AI 生成 UI 模式。
- 产品真理持久化：通过 init 命令生成 PRODUCT.md，将受众、约束等核心事实与视觉设计分离。
- 实时浏览器迭代：支持在浏览器中直接对元素进行变体生成和实时调整。
- Rust 引擎与 Hook 集成：核心逻辑由 Rust 编写的独立二进制文件驱动，支持深度集成到各类 AI 编程工具中。

**使用场景**：
- 前端开发团队：在使用 AI 工具开发时，强制 AI 遵循特定设计规范，避免生成千篇一律的模板。
- UI/UX 质量审查：在代码交付前，使用 audit（可访问性、性能）和 critique（层级、情感共鸣）命令进行深度检查。
- 设计系统维护：通过 extract 和 document 命令从现有代码中提取组件和设计令牌。
- 快速原型打磨：使用 polish、bolder 或 animate 等命令快速提升草稿页面的视觉表现力。

**需要注意的坑**：
- 工具生态依赖：必须配合特定的 AI 编程助手（如 Claude、Cursor、Codex）使用，在非支持工具上无法发挥核心作用。
- 权限配置繁琐：安装 Hook 后，需要在 Codex、Grok 等工具中手动开启信任权限，否则技能无法运行。
- 效果受限于模型：它本质上是技能包，最终质量取决于 AI 模型对指令的执行力和理解力。
- 本地环境要求：虽然 Rust 引擎自包含，但需要 Node.js 环境进行安装，且需要浏览器支持进行 Live 模式迭代。

- 希望利用现有付费订阅（如 Claude Code 计划）而无需额外购买昂贵自托管服务的团队。
