## 1. Nutlope/hallmark

**38,242⭐ · 今日 +2859 · CSS** · 创建于 2026-04-27 · [仓库](https://github.com/Nutlope/hallmark)

**它到底是什么**：这是一个专为 Claude Code、Cursor 和 Codex 等编码助手设计的“设计技能”，旨在拒绝生成“AI 糟粕”风格的页面。它内置 48 种主题素材，通过预检、主题分发、英雄区渲染和浏览器渲染检查（`sloplint`）四步工作流，强制执行高对比度、无机械感排版等设计规范，确保输出符合人类审美。

**核心机制**：
- Anti-AI Slop 检测机制：通过 `sloplint.mjs` 检测机械感特征（如标题上方的眉毛、全大写字母、单一彩色词、空框架等）。
- 材质设计系统：48 种主题，每个主题是一个最多 8KB 的 CSS/材质文件，包含纹理、颜色和组件定义。
- 三级门禁体系：Floor（硬性底线，如对比度、无断点布局）、Reflex（默认规则）、Finish（工艺细节）。
- Puppeteer 浏览器渲染检查：在真实浏览器中检查 8 个屏幕宽度，确保布局和交互正常。
- 预检流程：读取项目字体、调色板、框架，并锁定 `design.md`，不虚构内容。
- 自包含输出：生成的页面是独立的 HTML 和 CSS，并在 CSS 注释中记录了设计决策。

**使用场景**：
- 开发者使用 AI 编码助手快速构建具有人类审美风格的落地页。
- 团队需要审计现有网站，检查是否存在“AI 生成”的机械感设计缺陷。
- 对现有应用进行重设计，保留内容结构但改变视觉风格。
- 需要生成包含真实照片（CC0/公有领域）的页面。

**需要注意的坑**：
- 环境依赖重：不仅需要 Node.js 18+，还需要安装 Puppeteer 和 Chrome 浏览器才能运行完整的渲染检查。
- 安装配置繁琐：针对不同的 AI 编码助手（Claude Code、Codex、Cursor 等）需要不同的安装命令和路径，容易搞混。
- 非独立工具：它不是网页应用，而是嵌入在特定 AI 编码环境中的插件，无法直接在浏览器中运行。

## 4. pbakaus/impeccable

**90,047⭐ · 今日 +1458 · Rust** · 创建于 2025-11-16 · [仓库](https://github.com/pbakaus/impeccable)

**它到底是什么**：这是一个专为 AI 编码代理设计的前端设计规范工具，旨在防止 AI 生成陈旧、重复的 UI（如到处是 Inter 字体或嵌套卡片）。用户通过 `npx impeccable install` 安装后，可在 Claude、Cursor 等工具中使用 `/impeccable` 命令流（如 `audit`、`polish`、`critique`）对项目进行设计审计和打磨。它维护 `PRODUCT.md`（产品真相）和 `DESIGN.md`（视觉系统），并提供 62 条确定性规则在浏览器中实时检测设计缺陷。

**核心机制**：
- Rust 引擎：自包含二进制文件，无外部依赖，本地运行
- 确定性检测规则：62 条规则在本地运行，无需 LLM 或 API 密钥
- 技能命令流：24 个特定命令（`audit`、`polish` 等）与 AI 交互
- 双文件架构：`PRODUCT.md`（逻辑/语境）与 `DESIGN.md`（视觉）分离
- 浏览器扩展：用于实时视觉迭代和生成变体

**使用场景**：
- 使用 Claude Code 或 Cursor 等工具的 AI 辅助开发者
- 想要避免 AI 生成陈旧 UI（如嵌套卡片）的团队
- 需要严格设计审计（可访问性、性能）的团队
- 希望标准化 AI 设计输出的产品经理/设计师

**需要注意的坑**：
- 依赖 AI 工具的配合度（如果 AI 忽略技能，效果会打折扣）
- 钩子信任问题（Codex/Grok 需要手动批准钩子）
- 需要下载 Rust 二进制文件或链接子模块
- 学习曲线（需要理解 24 个命令的语义）

## 7. affaan-m/ECC

**290,476⭐ · 今日 +1183 · JavaScript** · 创建于 2026-01-18 · [仓库](https://github.com/affaan-m/ECC)

**它到底是什么**：ECC 是一个面向 AI 编程代理的“操作系统”，通过插件形式无缝集成到 Claude Code、Cursor 等开发工具中。它提供技能库、长期记忆、安全防护和研发优先的工作流，旨在提升 AI 代理在复杂开发任务中的执行效率和稳定性。

**核心机制**：
- 插件化集成架构：通过 `ecc@ecc` 插件挂载，统一管理 Claude Code、Codex、Cursor 等多种 AI 模型。
- 跨语言执行引擎：支持在沙箱环境中直接执行 Shell、TypeScript、Python、Go、Java 等多种编程语言。
- 安全沙箱机制：内置 Agent Shield 防护层，对 AI 生成的命令进行安全审查和拦截。
- 上下文记忆系统：持久化存储项目历史和技能，避免 AI 在重复任务中遗忘上下文。
- 研究优先工作流：集成搜索和工具调用，强制 AI 在执行代码前先进行调研和验证。

**使用场景**：
- 需要深度集成 AI 辅助编程的团队，希望统一管理多个 AI 模型并保持一致性。
- 开发者在 Cursor 或 Claude Code 中需要系统级的控制能力（如权限管理、记忆持久化）。
- 需要执行高风险系统命令（如部署、数据库操作）的场景，利用安全机制防止误操作。
- 长期维护的大型项目，利用记忆系统保持 AI 对项目历史和复杂依赖的理解。

**需要注意的坑**：
- 安装风险：必须从官方渠道（GitHub/NPM/官网）安装，第三方镜像可能被篡改植入恶意代码。
- 私有仓库限制：开源版仅限公开仓库，私有仓库需要购买 ECC Pro（按席位收费）。
- 配置复杂度：作为“操作系统”，配置项较多，对新手开发者有一定学习门槛。
