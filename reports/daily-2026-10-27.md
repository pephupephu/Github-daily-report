## 1. Nutlope/hallmark

**37,041⭐ · 今日 +2244 · CSS** · 创建于 2026-04-27 · [仓库](https://github.com/Nutlope/hallmark)

**它到底是什么**：Anti-AI-slop design skill for Claude Code, Cursor, and Codex. 它是一个强制 AI 编码代理生成高保真、类人 UI 的插件，通过 48 种预定义的“材料”主题、严格的排版规则以及真实的授权图片库，来替代 AI 常见的通用化设计缺陷。

**核心机制**：
- 48 种材料主题：提供 48 种预定义的设计系统（纸张、字体、色彩、纹理），AI 需根据提示选择一种作为设计基础，而非生成通用模板。
- Slop Linting（浏览器渲染检查）：使用 Puppeteer 在真实浏览器中渲染页面，并检查 8 种宽度下的“AI 痕迹”（如全大写字母间距过大、标题中仅一个彩色单词、空框架等）。
- 设计层级（Floor/Reflex/Finish）：强制执行硬性约束（如对比度、无障碍），默认检查（如布局合理性）和细节打磨（如微交互），层层过滤低质量输出。
- 真实图库：内置 755 张来自 Wikimedia Commons 的真实授权照片，替代 AI 生成的占位图，并自动在页面底部署名。
- 前置检查与分步构建：在构建前读取项目上下文（字体、调色板），并先构建 Hero 区域进行冷渲染审查，再进行全页构建。

**使用场景**：
- AI 编码助手用户：使用 Claude Code、Cursor 或 Codex 的开发者，希望直接生成接近人工设计的高质量前端页面。
- 快速原型开发：需要快速产出具有专业视觉效果的落地页、仪表盘或 SaaS 产品界面。
- UI 审计与重构：对现有看起来过于“AI 风格”的页面进行重构，或使用 `/hallmark audit` 命令检测页面是否存在设计缺陷。

**需要注意的坑**：
- 环境依赖重：不仅需要 Node.js 18+，还必须安装 Puppeteer 和本地 Chrome 浏览器才能运行渲染检查，无法像普通 CSS 库那样直接引入。
- 安装配置复杂：需要通过特定的 CLI 命令（如 `npx skills add`）安装，且针对不同 AI 代理（Claude vs Cursor）的配置路径不同，新手容易踩坑。
- 图片署名义务：虽然使用的是开源图片，但必须遵守其许可证（CC0, CC BY 等），在商业项目中使用时必须在页面底部保留原作者署名。
- 依赖 AI 执行力：该工具本质上是一套指令集，如果 AI 代理忽略指令或能力不足，无法保证输出效果。

- 实时漏洞库查询：集成 OSV.dev 查询实时 CVE 数据。
- 71种风险模式：覆盖提示注入、数据泄露、供应链、工具滥用等 17 个类别。
- 基线抑制机制：支持通过指纹或规则忽略已知误报。
- SARIF 输出：符合 CI/CD 标准的扫描报告格式。
- 资源限制：防止超大文件或 ZIP 炸弹导致资源耗尽。

**使用场景**：
- AI 代理技能开发者：在发布技能前进行自检。
- 企业安全团队：集成到 CI/CD 流水线中自动化扫描。
- 个人用户：在安装社区技能前检查安全性。
- 批量扫描：对整个技能目录进行并行扫描。

**需要注意的坑**：
- LLM 成本与延迟：开启 LLM 模式需要 API 密钥（如 DeepSeek/Anthropic），会产生费用且速度较慢。
- 第三方依赖风险：安装时会下载额外的开源软件，需注意其许可证条款。
- 输入大小限制：单次扫描有 100MB 的限制，超大技能包可能无法扫描。
- 维护与兼容性：默认后端使用 DeepSeek，若其服务变更或停止，可能影响扫描稳定性。

## 10. Panniantong/Agent-Reach

**104,044⭐ · 今日 +746 · Python** · 创建于 2026-02-24 · [仓库](https://github.com/Panniantong/Agent-Reach)

**它到底是什么**：Agent Reach 是一个 CLI 工具，为 AI Agent 提供访问受限互联网平台（如 Bilibili、小红书、Twitter、Reddit）的能力，无需 API 密钥。它通过封装特定的抓取工具（如 bili-cli、yt-dlp）并管理浏览器会话，将非结构化网页和视频内容转换为结构化数据，让 Agent 能执行搜索、读字幕和访问需登录网站。

**核心机制**：
- 多工具故障转移策略：每个平台动作都有首选工具（如 Jina Reader）和备选工具（如 Exa）的有序列表，失败时自动切换。
- 浏览器会话复用：通过复制 Chrome 的登录 Cookie 避免频繁弹窗登录，实现无感访问需登录平台。
- CLI 封装层：将复杂的抓取逻辑封装为简单命令（如 agent-reach bilibili search），供 Agent 直接调用。
- 结构化数据提取：利用上游工具将 HTML/视频清洗为 JSON 格式，便于 LLM 处理。
- 本地化部署：所有工具和会话存储在本地目录，不依赖云端 API，降低成本。

**使用场景**：
- AI Agent 开发者：为 Claude、OpenAI 等大模型 Agent 增加访问特定中文平台或视频平台的能力。
- 数据分析师：需要抓取需要登录的网站（如 LinkedIn、Reddit）或视频字幕，且不想编写复杂爬虫。
- 隐私敏感用户：需要读取互联网内容但不想使用付费 API，且希望数据保留在本地。

**需要注意的坑**：
- 反爬虫风险：高频抓取仍可能触发目标网站的反爬虫机制，导致 IP 被封或请求失败。
- 维护成本高：依赖第三方 CLI 工具，若上游工具更新或失效，需手动更新工具列表。
- 权限与安全性：需要安装系统级依赖和复制浏览器 Cookie，存在一定的权限风险和账号泄露隐患。
- 合规性风险：自动化抓取行为可能违反部分网站的服务条款（ToS）。
