- 兼容性限制：并非所有 AI 代理都支持插件系统，部分工具需要手动配置或使用命令行参数。
- 上下文占用：如果技能定义过长，可能会占用宝贵的上下文窗口。

**核心机制**：
- CLI 代理模式：T3 Code 通过调用各 AI 工具的本地 CLI 命令（如 `codex login`）来执行操作，本身不生成代码，而是充当调度器。
- Electron/Web 混合架构：提供跨平台的桌面应用和 Web 界面，通过本地网络与运行 `t3` 服务器的机器通信，实现远程控制。
- 远程访问支持：允许用户通过手机 App 或另一台机器的浏览器连接到本地服务器，实现跨设备操作。
- Vite+ 构建系统：使用 Vite+ 作为构建工具链，支持快速开发和打包 Electron 应用。
- 多账户/多工具集成：支持同时管理多个 AI 服务的不同账户（如多个 Claude 账号或 Codex 账号）。
- 权限模式控制：支持配置不同的权限模式，决定 AI 代理在执行操作时的权限范围。
- 后台服务模式：支持将 `t3` 服务安装为系统后台服务，确保机器重启后自动运行。

**使用场景**：
- 远程移动开发：开发者在手机上通过 T3 Code 的 iOS/Android App 控制电脑上的 AI 工具，进行代码审查或简单修改。
- 多工具统一调度：同时使用 Cursor、Claude Code 和 Codex，需要一个统一的界面来切换和调度不同的 AI 代理。
- 本地化 AI 工作流：在本地服务器运行 AI 工具，通过 T3 Code 的 Web 界面进行交互，避免云端 API 费用或隐私担忧。
- 跨设备协作：在办公室的电脑上启动服务，在家的手机上通过远程访问继续工作。

**需要注意的坑**：
- 项目极度早期：作者明确警告“Expect bugs”，功能可能不稳定，不适合作为生产环境的唯一依赖。
- 贡献门槛高：目前（主要）不接受社区贡献，大功能不会实现，遇到 Bug 只能等作者修复。

## 6. milind-soni/OpenMausBot

**9,830⭐ · 今日 +1303 · TypeScript** · 创建于 2026-08-11 · [仓库](https://github.com/milind-soni/OpenMausBot)

**它到底是什么**：这是一个基于 Electron 的开源桌面应用，作为 Grok Bot 的本地替代品，它将多个 AI Agent（如 Claude、Codex）整合到一个类似 Telegram 的聊天界面中。用户无需购买新账号，只需在本地运行现有的 AI 命令行工具，即可在侧边栏拥有多个拥有独立性格、记忆和‘手脚’（可调用云桌面或应用）的 AI 机器人。

**核心机制**：
- Electron 桌面应用架构，支持 macOS、Windows 和 Ubuntu
- ‘自带 Agent’ 机制，通过本地 CLI（如 `claude`, `codex`）连接用户已安装的模型
- 本地 Harness 服务器（`127.0.0.1`），负责管理所有 Agent 进程、存储对话记录和密钥
- 多 Agent 隔离机制，每个机器人拥有独立的模型配置、性格设定和云桌面/本地虚拟机环境
- Composio 集成，允许 Agent 调用 500+ 外部应用
- 主机控制机制，在 macOS 和 Ubuntu Xorg 上支持显式授权后控制本地硬件

- 注重隐私的开发者或个人用户，希望将 AI 对话和 Agent 执行环境完全保留在本地，不经过第三方云服务商
- 需要同时管理不同模型（如 Claude 写代码，Grok 写文案）的用户，通过侧边栏切换不同 Agent
- 需要具备‘手脚’的 Agent 进行自动化测试、操作云桌面或本地应用的场景
- 寻找开源替代品（替代 Grok Bot, Meta Muse, OpenAI dots）的极客

**需要注意的坑**：
- 依赖本地环境，必须预先安装并配置好 `claude`, `codex` 等命令行工具，否则无法运行
- 硬件负载高，运行多个 Agent 或虚拟机需要较强的本地算力和内存支持
- 平台限制，Ubuntu Wayland 下的主机控制功能目前被禁用（Issue #345），且需要显式授权才能控制本地硬件
- 合规风险，虽然软件本身开源，但调用 OpenAI/Meta 等大模型仍需遵守其各自的 API 服务条款

- 持久化与恢复：支持会话恢复、知识库自同步及回收站功能，防止数据丢失。

- 自学者构建个人知识库，通过对话式交互复习特定领域的文档或书籍。

- 定时自动化：支持按小时/天/周/月触发任务。
