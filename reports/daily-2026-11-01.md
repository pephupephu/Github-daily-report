## 1. thedotmack/claude-mem

**108,205⭐ · 今日 +1723 · TypeScript** · 创建于 2025-08-31 · [仓库](https://github.com/thedotmack/claude-mem)

**它到底是什么**：这是一个为 Claude Code 及其他 AI 编程工具设计的持久化上下文系统。它通过安装一个“观察者”插件，自动捕获 AI 在会话中的所有操作（如工具调用、决策、Bug 修复），利用大模型将其压缩为语义摘要，并在新会话开始时自动注入上下文，从而解决 AI 会话断开后遗忘项目历史的问题。

**核心机制**：
- Observer Pattern (观察者模式)：作为插件运行，实时监听 IDE 或工具的日志流和事件。
- Context Capture (上下文捕获)：自动识别并记录关键操作，包括决策、Bug 修复、安全警报等。
- AI Compression (AI 压缩)：利用大模型（如 Claude、Gemini）将原始日志转化为结构化的语义摘要。
- Session Injection (会话注入)：在新会话初始化时，将压缩后的记忆作为系统提示词或上下文注入。
- Multi-Provider Storage (多提供商存储)：支持云端 CMEM Pro、本地 OpenRouter/Gemini 或 Anthropic 计划作为记忆后端。

**使用场景**：
- 长周期项目开发：开发者需要 AI 在几天甚至几周后继续处理同一个复杂项目，无需重新解释背景。
- 多会话协作：团队成员在不同时间启动会话，AI 能通过记忆保持对项目状态的一致理解。
- CI/CD 环境：在非交互式或 CI 环境中运行，通过环境变量配置，无需浏览器登录。
- 多工具切换：在 Claude Code、OpenCode、T3 Code 等不同 IDE 间切换时，保持记忆连贯。

**需要注意的坑**：
- 依赖重启生效：安装后必须重启 IDE（如 OpenCode、T3 Code）才能加载插件，否则无法工作。
- 环境要求：需要 Node.js >= 20.0.0，且在 CI 环境中需设置 `CLAUDE_MEM_ONLINE_OPTIN=false` 以跳过交互式登录。
- 数据隐私风险：默认使用云端 CMEM Pro，涉及敏感代码的隐私需确认服务条款；若用本地模型需自行承担算力成本。
- 敏感数据记录：默认会记录安全警报等敏感信息，需注意合规性。

## 5. Renhuai123/ziwei-doushu

**核心机制**：
- 倪海厦《天纪》体系算法：基于特定流派（如现代修正v2与《斗数全书》亮度）的排盘逻辑，包含真太阳时校正、中国夏令时判定及钟表时间标准化。
- JSONL 数据集：采用JSON Lines格式存储命盘与解读，每行包含公历日期、时辰序号、性别及13维Markdown文本。
- zstd 长窗口压缩：数据集使用zstd算法压缩，需开启`--long=27`参数才能解压，单文件解压后达56.6GB。
- 确定性生成：解读文本由排盘引擎+断语库生成，非AI随机，同一输入恒得同一输出。
- 分层许可机制：代码MIT，数据集CC BY 4.0（可商用），但引用的倪海厦原话受CC BY-NC-SA 4.0限制（不可商用）。

**使用场景**：
- 命理从业者：利用开源引擎快速生成命盘，或使用离线数据集进行批量批注和客户咨询。
- 开发者：基于TypeScript引擎开发Web/App端命理工具，或集成到现有系统中。
- 学术/数据研究者：分析海量命盘数据（67.5万张）与解读文本的关联性，挖掘命理规律。
- 教育机构：作为教学辅助工具，让学生通过真实命盘理解倪海厦《天纪》的理论体系。

**需要注意的坑**：
- 数据体积巨大：v4.0数据集解压后达56.6GB，下载和解压对硬盘和带宽要求较高。
- 许可边界模糊：虽然数据集本身可商用，但引用的倪海厦原话受CC BY-NC-SA 4.0限制，直接引用需注意合规。
- 时辰逻辑陷阱：`h`字段是0-11的地支序号，而非0-23的小时数，容易导致排盘错误。
- 未来日期：数据集覆盖至2026年，若用于严肃的历史研究可能存在数据时效性问题。
