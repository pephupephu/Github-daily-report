## 6. nvm-sh/nvm

**96,212⭐ · 今日 +237 · Shell** · 创建于 2010-04-15 · [仓库](https://github.com/nvm-sh/nvm)

**它到底是什么**：nvm 是一个 Node.js 版本管理工具，通过 bash 脚本在命令行中安装和使用不同版本的 Node.js。使用 `nvm install <version>` 安装指定版本的 Node.js，使用 `nvm use <version>` 切换当前使用的 Node.js 版本，使用 `nvm ls` 列出已安装的版本。

**核心机制**：
- 基于 POSIX-compliant 的 bash 脚本，通过修改 shell 配置文件（如 `.bashrc` 或 `.zshrc`）来加载 Node.js 环境
- 使用 `nvm.sh` 脚本动态修改 `PATH` 环境变量，以便在当前 shell 会话中使用指定版本的 Node.js
- 通过 `git`、`curl` 或 `wget` 下载和安装 nvm，并克隆 nvm 仓库到 `~/.nvm` 目录
- 支持 `.nvmrc` 文件自动切换项目所需的 Node.js 版本
- 提供 `nvm install`, `nvm use`, `nvm ls` 等命令来管理 Node.js 版本
- 兼容多种 POSIX-compliant shell，如 bash、zsh、ksh 等
- 支持离线安装 Node.js 二进制文件
- 允许自定义 Node.js 二进制文件的镜像源

**使用场景**：
- 前端开发人员需要在不同项目间切换不同版本的 Node.js
- Node.js 开发者需要测试不同版本 Node.js 对项目的影响
- CI/CD 工程师需要在构建环境中使用特定版本的 Node.js
- 系统管理员需要在多用户环境中为不同用户管理 Node.js 版本

**需要注意的坑**：
- 安装脚本可能修改错误的 shell 配置文件，需要手动调整 `NVM_DIR` 和 `PROFILE` 环境变量
- 在 Docker 容器中使用 nvm 需要特殊处理 `BASH_ENV` 环境变量，否则可能无法正常加载
- nvm 不支持 Windows 系统的原生命令行环境，需要在 WSL 或其他兼容环境中使用

- 服务器可以本地运行，也可以作为云服务提供，支持多种编程语言和操作系统。
- 服务器通过编程接口与客户端交互，客户端可以是各种AI模型或应用。
- 部分服务器提供聚合功能，可以整合多个工具和服务的输出，简化模型的使用。

**使用场景**：
- AI研究人员和开发者可以使用这些服务器来扩展AI模型的功能，使其能够访问更多外部资源。
- 企业可以使用这些服务器来构建更智能的应用，如自动化工具、数据分析平台等。
- 教育机构可以使用这些服务器来教授AI和MCP相关的知识和技术。

**需要注意的坑**：
- 部分服务器可能需要特定的硬件或软件环境才能正常运行。
- 一些服务器的许可协议可能限制其在商业环境中的使用。
