插件可以通过 Claude Code 的插件系统直接从该市场安装。

要安装，请运行“/plugin install {plugin-name}@claude-plugins-official”

### 外部插件

第三方合作伙伴可以提交插件以纳入市场。外部插件必须符合质量和安全标准才能获得批准。要提交新插件，请使用[插件目录提交表单](https://clau.de/plugin-directory-submission)。

## 插件结构

每个插件都遵循标准结构：

````
插件名称/
├── .claude-plugin/
│ └── plugin.json # 插件元数据（必填）
├── .mcp.json # MCP 服务器配置（可选）
├── 命令/ # 斜杠命令（可选）
├── Agents/ # 代理定义（可选）
├── Skills/ # 技能定义（可选）
└── README.md # 文档
````

## 插件名称是不可变的

市场条目中的“名称”字段是一个**不可变的slug**。一旦插件发布，它的“名称”就不能改变——用户将其安装在该插件下，重命名它会破坏他们的安装，并出现“插件未找到”错误。

- 要更改插件在 UI 中的标记方式，请设置或更新“displayName”。
- 如果重命名确实不可避免，请在“.claude-plugin/marketplace.json”中的顶级“renames”映射中添加一个条目，以便现有安装自动迁移：

```json
“重命名”：{
 "旧名称": "新名称"
}
````

Claude Code 插件加载器读取此映射，并在用户下次同步时透明地将旧的 slug 重写为新的 slug。

## 技能包插件

当插件的源存储库在没有“.claude-plugin/plugin.json”清单的情况下发布技能（“SKILL.md”文件）时，市场条目可以直接使用“strict: false”和显式“skills”数组声明技能。

```json
{
 “名称”：“示例包”，
 "description": "捆绑技能的简要描述。",
 "author": { "name": "作者姓名" },
 “类别”：“开发”，
 “来源”：{
 “来源”：“git-subdir”，
 “url”：“https://github.com/example-org/sdk.git”，
 “路径”：“包/代理技能”，
 “参考”：“主要”，
 “煞”：“”
 },
 “严格”：假，
 “技能”：[
 "./技能-a",
 "./技能-b",
 “./技能-c”
 ],
 “主页”：“https://github.com/example-org/sdk”
}
````

“skills”中的每个路径都相对于“source.path”，并指向包含“SKILL.md”的目录。路径可以比单个级别更深 - 例如，`["./libA/skill-1", "./libB/skill-2"]`公开跨多个库子目录的精选子集。每个技能在 Claude Code 中都被注册为 `:`。

有关底层架构，请参阅市场文档中的[严格模式](https://code.claude.com/docs/en/plugin-marketplaces)。

## 问题

每个 MCP 工具调用都会将原始数据转储到上下文窗口中。 Playwright 快照的大小为 56 KB。二十个 GitHub 问题花费 59 KB。一份访问日志 — 45 KB。 30 分钟后，40% 的上下文就消失了。当代理将对话压缩为可用空间时，它会忘记正在编辑哪些文件、正在进行哪些任务以及您上次请求的内容。最重要的是，代理将输出令牌浪费在填充物、寒暄和冗长的解释上——双方都在浪费上下文。

### 上下文模式如何解决这个问题

上下文模式是一个 MCP 服务器，它解决了这个问题的所有四个方面：

1. **上下文保存** — 沙盒工具将原始数据保留在上下文窗口之外。 315 KB 变为 5.4 KB。减少 98%。

2. **会话连续性** — 每个文件编辑、git 操作、任务、错误和用户决策都在 SQLite 中跟踪。当对话压缩时，上下文模式不会将这些数据转储回上下文中 - 它将事件索引到 FTS5 中，并通过 BM25 搜索仅检索相关内容。该模型会准确地从您上次停下的地方继续。如果您不“--继续”，先前的会话数据将立即删除 - 一个新的会话意味着一个干净的状态。
3. **用代码思考** — 法学硕士应该对分析进行编程，而不是计算。代理不会将 50 个文件读入上下文来计数函数，而是编写一个执行计数的脚本，并且“console.log()”仅输出结果。一个脚本可替代十个工具调用并节省 100 倍的上下文。这是所有 17 个受支持客户端的强制范例，加上 OpenClaw 网关集成：停止将 LLM 视为数据处理器，而将其视为代码生成器。

 ````js
 // 之前：47 × Read() = 700 KB。 之后：1 × ctx_execute() = 3.6 KB。
 ctx_execute(“javascript”，`
 const 文件 = fs.readdirSync('src').filter(f => f.endsWith('.ts'));
 files.forEach(f => console.log(f + ': ' + fs.readFileSync('src/'+f,'utf8').split('\\n').length + 'lines'));
 `);
 ````

4. **没有散文式的强制** - 上下文模式使原始数据脱离上下文，但从不规定模型如何编写其最终答案。简洁、完整性、格式——您的模型的调用（或者您通过您自己的“CLAUDE.md”/“AGENTS.md”进行的调用）。过分简洁的提示已被证明会降低编码/推理基准（[Moonshot AI on `kimi-k2.5`](https://github.com/anomalyco/opencode/issues/20258)）——路由块始终关注*数据去向*，而不是*模型如何对话*。

它从您启动编码代理的那一刻开始。一旦它发现您正在构建某些东西，它就不会立即尝试编写代码。相反，它会退后一步，问你真正想做什么。

一旦它从对话中挑出一个规范，它就会以足够短的块向您展示，以便您实际阅读和消化。 

在您签署设计后，您的代理会制定一个实施计划，该计划对于一位品味差、缺乏判断力、没有项目背景且厌恶测试的热情初级工程师来说足够清晰。它强调真正的红/绿 TDD、YAGNI（你不需要它）和 DRY。 

接下来，一旦您说“开始”，它就会启动“子代理驱动开发”流程，让代理完成每个工程任务，检查和审查他们的工作，然后继续前进。对于您的代理来说，在不偏离您制定的计划的情况下一次自主工作几个小时的情况并不少见。

还有很多东西，但这是系统的核心。而且因为技能会自动触发，所以你不需要做任何特别的事情。你的编码特工拥有超能力。

## 将其放入任意文件夹

参考编码是同一原语的一种使用：“xerj autoindex”创建一个代理
了解语料库而不是抓取它。一个命令可以索引代码、文档、日志、PDF、SQLite 和
将笨拙的 CSV 转换为类型化、可查询的索引，用于搜索、RAG、安全审计和代理
内存，无需写入模式，也无需配置管道。

````嘘
xerj --insecure --data-dir ./data & # 启动它
xerj autoindex ~/my-project # 将其指向任何内容
````
