## 1. erkamyaman/rust-anything

**10,544⭐ · 今日 +0 · Rust** · 创建于 2026-11-16 · [仓库](https://github.com/erkamyaman/rust-anything)

**它到底是什么**：Rust Anything 是一个工具，允许开发者逐步将现有应用程序从 TypeScript、JavaScript、Python、Go、Ruby、Java、C、PHP、C#、Kotlin 和 PowerShell 等语言迁移到 Rust，并在每一步都将其与原始应用程序进行对比以确保行为一致。

**核心机制**：
- 利用静态分析技术对源代码进行解析和转换
- 通过抽象语法树（AST）操作实现语言间的代码转换
- 采用插件架构支持多种源语言和目标语言
- 集成代码覆盖率测试确保转换后的功能一致性
- 利用 Rust 的类型系统和所有权模型优化代码性能
- 支持与大型语言模型（LLM）集成进行智能代码转换

**使用场景**：
- 需要将现有应用程序迁移到 Rust 的开发者
- 希望在 Rust 环境中利用现有代码库的企业
- 需要进行多语言代码重构和优化的研究机构
- 追求高性能和内存安全性的软件开发团队

**需要注意的坑**：
- 许可：虽然提供 MIT 或 Apache-2.0 许可，但需注意贡献代码的许可兼容性
- 硬件：Rust 编译过程可能需要较高的计算资源，尤其是在处理大型代码库时
- 成熟度：作为开源项目，部分功能可能不如商业工具完善，需要一定的调试和优化

## 4. EL4CTEO/fast-anything

**4,371⭐ · 今日 +0 · Rust** · 创建于 2026-11-21 · [仓库](https://github.com/EL4CTEO/fast-anything)

**它到底是什么**：fast-anything 是一个用 Rust 重写慢速函数的工具，通过分析 Python、Node.js、Ruby 等应用程序，找出最耗时的 5% 函数，并将其用 Rust 重写，同时确保重写后的函数行为与原函数一致。使用命令 `fast-anything go --agent claude -- python app.py` 可以指定编程代理和要分析的应用程序，它会自动识别慢速函数并生成 Rust 代码，然后进行验证和替换。

**核心机制**：
- 基于性能分析（profile）识别应用程序中最耗时的函数
- 使用编程代理（如 Claude Code 或 Codex）将慢速函数从 Python、Node.js、Ruby 等语言转换为 Rust
- 通过记录和重放真实调用（up to 500 个）来验证 Rust 函数的行为是否与原函数一致
- 使用 Rust 工具链编译和优化重写的函数
- 提供 `enable`/`disable` 命令来切换 Rust 函数的启用状态，实现无缝替换
- 通过 `bench` 命令进行 A/A 测试，确保性能提升的真实性
- 使用 `report` 生成 PR 报告，方便代码审查
- 支持多种编程语言和框架，包括 Python、Node.js、TypeScript、Ruby、Java、Kotlin、Go、PHP、C、C++、C# 和 R

**使用场景**：
- 开发人员希望优化现有应用程序的性能，但不想重写整个应用程序
- 需要将特定函数的高性能需求从解释型语言（如 Python）迁移到编译型语言（如 Rust）
- 在保持原有代码逻辑不变的情况下，提高应用程序的响应速度和吞吐量
- 用于科学计算或数据处理等对性能要求较高的场景

**需要注意的坑**：
- 需要一定的 Rust 编程知识来理解和维护重写的函数
- 许可为 MIT，但需要确保编程代理（如 Claude Code 或 Codex）的合规性
- 在某些情况下，重写的函数可能比原函数慢（例如，调用 Rust 函数的开销大于节省的时间）
- 对于非常小的函数或调用次数很少的函数，重写可能不值得

## 5. AFK-surf/xnulinux

**4,305⭐ · 今日 +0 · C** · 创建于 2026-11-20 · [仓库](https://github.com/AFK-surf/xnulinux)

**它到底是什么**：xnulinux 允许在未修改的 arm64 Linux 内核中加载并运行 macOS 内核，从而在同一个 CPU 上原生运行 macOS 和 Linux 进程，无需虚拟机或 Hypervisor。通过加载 `xnu.ko` 模块，XNU 直接控制 CPU 和 MMU，而 Linux 通过 `fki.ko` 模块提供内存、计时器、文件、网络和 GPU 等资源。使用 `insmod xnu.ko` 命令可以启动 macOS 系统磁盘，并运行 loginwindow、WindowServer、Dock、Finder、Safari 和 Chrome 等 macOS 应用。

**核心机制**：
- XNU 内核直接控制 CPU 和 MMU，实现 macOS 进程的原生运行
- Linux 通过 FKI (Foreign Kernel Interface) 模块提供内存、计时器、文件、网络和 GPU 等资源
- XNU 和 Linux 共享用户地址空间布局，使用 4K 页面进行内存管理
- kexts 模块为 macOS 提供磁盘、显示、键盘指针、网络接口、密钥库和 GPU 桥接等设备支持
- GPU 通过 Metal 到 Vulkan 的转换，再通过 DRM 桥接使用 Linux 主机的 GPU

**使用场景**：
- 开源情报分析师需要在 Linux 环境中运行 macOS 应用进行逆向分析或漏洞研究
- 研究人员需要测试 macOS 特定软件在 Linux 上的兼容性
- 开发者需要在没有 macOS 硬件的 Linux 机器上测试 macOS 软件
- 教育机构需要提供 macOS 环境进行教学实验

**需要注意的坑**：
- 需要 arm64 Linux 主机且支持 PAC、4K 页面，至少需要 16GB RAM（8GB 用于 XNU）
- 需要 Mac 和 Xcode 来制作 macOS 系统磁盘和构建 GPU 部分，且不能使用 Apple 二进制文件
- GPU 支持不完全，目前仅支持 virtio-gpu，硬件 GPU 过渡需要新的 DRM 桥接后端
- 内存访问速度较慢（4K 页面 vs 16K 页面），系统加密和 SIP 配置需要特殊处理

## 12. INK-Q/agy-fast

**1,846⭐ · 今日 +0 · TypeScript** · 创建于 2026-11-19 · [仓库](https://github.com/INK-Q/agy-fast)

**它到底是什么**：agy-fast 是一个用于 Google Antigravity（CLI、桌面版和 IDE）的非侵入式 MCP 加速插件，通过批量处理高频搜索、多语言符号轮廓、原子多文件编辑和构建/测试检查，将它们整合为批量本地调用，并每会话注入一次亚 50 毫秒的工作区快照，从而减少代理的 wall-clock 延迟（约 -33.7% LLM 转换）、计费 token 配额（约 -31.5%）和上传流量（约 -39.7%），而不影响 Antigravity 的原生 UI 或差异查看器。

**核心机制**：
- 利用 Model Context Protocol (MCP) 进行本地批量处理，减少不必要的网络请求
- 通过 `SessionStart` 钩子注入工作区快照，避免冷启动时的重复检查
- 整合高频搜索、文件编辑和构建测试为单个 MCP 调用，减少串行操作开销
- 支持多种安装方式，包括一键安装、本地克隆和直接克隆到 Antigravity 插件目录
- 提供 `--dangerously-skip-permissions` 选项，可自动批准工具权限请求（仅限可信环境）

**使用场景**：
- Google Antigravity 用户希望在保持原生 UI 体验的同时提高代理效率
- 需要处理大量文件编辑、搜索和构建测试的开发者或团队
- 对 token 配额和上传流量敏感的用户，希望降低成本

**需要注意的坑**：
- 需要 Node.js 20 或更高版本，且插件依赖预构建的 ESM 包，无 `npm install` 选项
- 自动批准权限的选项存在安全风险，仅建议在受控环境中使用
- 部分安装方式需要手动操作，可能对新手不够友好
