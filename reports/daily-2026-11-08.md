## 1. vercel-labs/agent-browser

**47,017⭐ · 今日 +190 · Rust** · 创建于 2026-01-11 · [仓库](https://github.com/vercel-labs/agent-browser)

**它到底是什么**：agent-browser 是一个用 Rust 编写的本地 CLI 工具，用于驱动浏览器自动化，允许 AI 代理逐条命令控制浏览器。它可以打开网页，将页面作为可访问性树读取，并通过 shell 对元素进行操作。使用 `snapshot` 命令可以获取页面的紧凑文本表示，每个元素都有一个引用（如 `@e1`），AI 代理可以通过这些引用对页面元素进行操作，然后重新读取页面以检查结果，浏览器在命令之间保持打开状态，因此每个步骤都是一条简短的 shell 调用。

**核心机制**：
- 基于 Chrome DevTools Protocol 控制浏览器
- 使用 Rust 构建 CLI 工具
- 提供可访问性树结构来描述页面元素
- 通过引用（refs）对页面元素进行操作
- 支持多种选择器（CSS、XPath、语义定位器）
- 支持会话持久化功能
- 支持多种浏览器引擎（Chrome for Testing、Lightpanda、Obscura、iOS Simulator）和云浏览器提供商
- 提供技能库以支持 AI 代理的自动化任务

**使用场景**：
- AI 代理需要进行网页自动化任务的开发者
- 需要从 shell 端口控制浏览器的自动化测试场景
- 需要集成浏览器自动化功能的 AI 应用
- 需要从命令行界面进行网页数据提取和处理的情况

**需要注意的坑**：
- 需要安装 Chrome for Testing 或其他浏览器引擎，可能涉及额外的硬件资源消耗
- 引用（refs）的有效性依赖于快照时间，DOM 变化后需要重新获取快照
- 某些元素（如隐藏、禁用或不在视口内的元素）可能导致操作失败，需要手动处理

## 14. ranxianglei/billion-context

**它到底是什么**：billion-context 是一个用于长会话（月级，数十亿 token）的上下文压缩插件，能在保持高压缩质量的同时，将大上下文窗口（100k 足够）减少 5 倍 token。使用后，可以在命令行通过 `billion-context` 压缩任何代理（如 Claude、OpenAI Codex 等）的输出流，将对话内容压缩成摘要，支持增量、可逆压缩，避免硬性截断。

**核心机制**：
- acp-kernel 压缩协议：在代理和模型 API 之间插入，重写输出流进行压缩
- 增量、可逆压缩：模型决定何时以及压缩什么内容为高保真摘要，而非硬性截断
- 分层摘要：将消耗的对话分层压缩，支持长会话持续运行
- 模型驱动压缩：由模型自主决定压缩时机和内容，非固定算法
- 高效的缓存机制：保持 95-97% 的前缀缓存命中率，压缩本身成本 ≤2%

**使用场景**：
- 需要长时间连续使用 AI 代理进行编码或对话的用户，如开发者、研究人员
- 当代理的上下文窗口限制（如 100k）不足以支持长时间会话时
- 希望显著减少 token 消耗，降低使用成本的场景

**需要注意的坑**：
- 依赖上游缓存 TTL 和模型行为，缓存命中率受多种因素影响
- 压缩质量和效果依赖于具体使用的代理和模型，并非所有模型都兼容或效果理想
