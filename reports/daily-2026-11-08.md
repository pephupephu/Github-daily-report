## 1. vercel-labs/agent-browser

**46,892⭐ · 今日 +190 · Rust** · 创建于 2026-01-11 · [仓库](https://github.com/vercel-labs/agent-browser)

**它到底是什么**：agent-browser 是一个用 Rust 编写的原生 CLI 工具，用于自动化浏览器操作，允许 AI 代理逐条命令控制浏览器，通过 `snapshot` 命令获取页面的紧凑文本表示，并使用引用（如 `@e1`）来操作页面元素，AI 代理可以读取页面检查结果并重复操作，浏览器在命令之间保持打开状态，每个步骤都是一条简短的 shell 调用。

**核心机制**：
- 使用 Chrome DevTools Protocol 控制浏览器
- 通过 snapshot 命令获取页面的可访问性树结构
- 使用引用（ref）来定位和操作页面元素
- 支持 CSS 选择器、XPath 和语义定位器
- 通过后台守护进程管理浏览器会话
- 支持多种浏览器引擎和云浏览器提供商
- 提供多种命令用于导航、交互、等待和捕获页面状态

**使用场景**：
- AI 代理需要自动化浏览器操作的场景，如网页数据抓取、自动化测试、网页交互任务
- 需要与网页进行复杂交互的 AI 应用，如填写表单、点击按钮、处理弹窗
- 需要实时监控网页变化的场景，如股票行情监控、新闻聚合

**需要注意的坑**：
- 需要安装 Chrome for Testing 或其他浏览器引擎，可能需要额外配置
- 引用（ref）的生命周期有限，页面变化后需要重新获取 snapshot
- 某些操作可能因元素状态（如隐藏、禁用）失败，需要处理覆盖元素的情况

**它到底是什么**：Prometheus 是一个开源的监控系统和时间序列数据库，它通过 HTTP 拉取模型从配置的目标收集指标数据，支持使用 PromQL 查询语言进行数据分析，并能根据规则表达式触发警报。用户可以通过配置文件定义监控目标、规则和警报条件，并通过 Web 界面查看监控数据和警报信息。

**核心机制**：
- 多维度数据模型：使用指标名称和键值对维度定义时间序列数据。
- PromQL 查询语言：提供强大的灵活性和功能，用于查询和分析多维时间序列数据。
- 单节点自主性：单个服务器节点可以独立运行，不依赖分布式存储。
- HTTP 拉取模型：Prometheus 定期主动从配置的目标拉取指标数据。
- 推送门关：支持通过中间件推送时间序列数据，适用于批处理作业。
- 服务发现：支持通过服务发现机制或静态配置自动发现监控目标。
- 图形化支持：支持多种图形化和仪表盘展示方式，并支持联邦机制进行数据聚合。
- 远程写入：支持将时间序列数据写入远程存储系统，如远程 Prometheus 或时间序列数据库。

**使用场景**：
- 云原生环境下的系统和应用监控。
- 需要实时监控和告警的分布式系统。
- 需要多维数据分析和可视化的监控场景。
- 需要与 Kubernetes 等容器编排平台集成的监控环境。

**需要注意的坑**：
- Prometheus 本身不提供分布式存储，数据存储和查询压力集中在单个节点上。
- PromQL 学习曲线较陡峭，需要一定的 SQL 和时间序列数据分析基础。
- 服务发现机制的配置和管理相对复杂，需要根据实际环境进行定制化配置。
