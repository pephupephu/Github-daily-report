````

## 插件名称是不可变的

市场条目中的“名称”字段是一个**不可变的slug**。一旦插件发布，它的“名称”就不能改变——用户将其安装在该插件下，重命名它会破坏他们的安装，并出现“插件未找到”错误。

- 要更改插件在 UI 中的标记方式，请设置或更新“displayName”。
- 如果重命名确实不可避免，请在“.claude-plugin/marketplace.json”中的顶级“renames”映射中添加一个条目，以便现有安装自动迁移：

```json
“重命名”：{
 "旧名称": "新名称"
}
````

Claude Code 插件加载器读取此映射，并在用户下次同步时透明地将旧的 slug 重写为新的 slug。

## 技能包插件

当插件的源存储库在没有“.claude-plugin/plugin.json”清单的情况下发布技能（“SKILL.md”文件）时，市场条目可以直接使用“strict: false”和显式“skills”数组声明技能。

```json
{
 “名称”：“示例包”，
 "description": "捆绑技能的简要描述。",
 "author": { "name": "作者姓名" },
 “类别”：“开发”，
 “来源”：{
 “来源”：“git-subdir”，
 “url”：“https://github.com/example-org/sdk.git”，
 “路径”：“包/代理技能”，
 “参考”：“主要”，
 “煞”：“”
 },
 “严格”：假，
 “技能”：[
 "./技能-a",
 "./技能-b",
 “./技能-c”
 ],
 “主页”：“https://github.com/example-org/sdk”
}
````

“skills”中的每个路径都相对于“source.path”，并指向包含“SKILL.md”的目录。路径可以比单个级别更深 - 例如，`["./libA/skill-1", "./libB/skill-2"]`公开跨多个库子目录的精选子集。每个技能在 Claude Code 中都被注册为 `:`。

有关底层架构，请参阅市场文档中的[严格模式](https://code.claude.com/docs/en/plugin-marketplaces)。

## 这是什么

结构化工作流程，将 Claude Code 转变为全栈职位申请助手。核心工作流程（自我分析、适合性评估和起草者-审阅者申请流程）**与语言和国家/地区无关**。职位门户搜索技能是为丹麦市场构建的（Jobindex、Jobnet、Akademikernes Jobbank 等），但该模式旨在替换为您当地的职位委员会。

````
/设置/刮擦/应用 

 维维维
填写 搜索职位 评估适合度
您的个人资料门户评分和推荐

 维维维
个人资料当前匹配简历草案+求职信

 伏
 选择匹配 审稿人评论
 -> /应用 -> 修改 -> 最终输出
````

该框架编码了职业指导最佳实践，包括结构化评估标准、前瞻性求职信框架和可选的薪资基准。
