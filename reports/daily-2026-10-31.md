## 1. thedotmack/claude-mem

**106,681⭐ · 今日 +1140 · TypeScript** · 创建于 2025-08-31 · [仓库](https://github.com/thedotmack/claude-mem)

**它到底是什么**：这是一个专为 Claude Code 及各类 AI 编程代理（如 Grok Bot、OpenCode）设计的持久化记忆系统。它通过监听代理的工具调用日志，利用 AI 进行语义压缩生成摘要，并将这些记忆存储在本地文件或云端，从而在后续会话中自动注入上下文，解决长对话或重启后上下文丢失的问题。

**核心机制**：
- 观察者模式：通过 IDE 钩子或日志文件监控代理的工具调用行为。
- 语义压缩：利用 LLM（Anthropic/OpenRouter/Gemini）将原始日志压缩为结构化摘要。
- MCP 协议集成：提供搜索工具，允许代理在记忆库中检索特定信息。
- 意识推送机制：识别关键事件（如决策、安全警报）并按日期标记。
- 多提供商架构：支持本地 API（OpenRouter/Gemini）和云端托管（CMEM Pro）两种存储方案。

**使用场景**：
- 长期项目维护：AI 需要跨越数天或数周记住项目的历史变更和架构决策。
- 多会话工作流：用户关闭终端后，再次打开时 AI 能自动加载之前的上下文。
- CI/CD 环境：在非交互式脚本中运行代理，避免因上下文丢失导致任务失败。
- 跨代理协作：在 Claude Code、Grok Bot 等不同代理间共享项目记忆。

**需要注意的坑**：
- API 成本：记忆压缩需要调用 LLM，使用云端 CMEM Pro 虽有免费试用但后续会产生额外费用。
- 隐私风险：若选择云端存储，项目敏感代码和日志会被发送至第三方服务器。
- 配置门槛：需要正确配置环境变量和 IDE 钩子，且部分 IDE（如 OpenCode）有版本要求。
- 依赖性：必须配合特定的 IDE 插件或钩子才能生效，无法独立运行。

## 8. mattpocock/skills

**307,675⭐ · 今日 +876 · Shell** · 创建于 2026-02-03 · [仓库](https://github.com/mattpocock/skills)

**它到底是什么**：这是一个面向 AI 编程助手的技能插件库，旨在提供‘真实工程师’的工作流而非‘氛围编码’。它包含一系列 Shell 脚本，通过 `/grill-me`（需求对齐）、`/tdd`（测试驱动开发）等命令，强制 AI 在编码前进行需求澄清、建立共享语言并执行红绿重构循环。

**核心机制**：
- 插件化安装：通过 `npx skills@latest add` 或各 Agent 的插件市场安装，将脚本注入到 `.agents` 目录。
- 需求对齐机制：`/grill-me` 和 `/grill-with-docs` 技能，在编码前强制 AI 询问详细问题，消除沟通鸿沟。
- 共享语言构建：利用 `CONTEXT.md` 文档建立领域术语表，减少 AI 词汇冗余，提高代码可读性和 Token 效率。
- 测试驱动循环：`/tdd` 技能强制 AI 先写失败测试（Red），再写功能代码（Green），最后重构（Refactor）。
- 配置即代码：`/setup-matt-pocock-skills` 命令用于初始化 Issue 追踪器、标签系统和文档存储路径。
- 自更新机制：部分插件支持自动更新，部分需手动运行 `npx skills@latest update`。

**使用场景**：
- 当 AI 编程助手无法准确理解模糊需求时，使用 `/grill-with-docs` 进行需求澄清。
- 当 AI 生成代码过于冗长或使用过多 Token 时，通过建立 `CONTEXT.md` 共享语言来优化。
- 项目开发需要严格的测试覆盖率时，强制使用 `/tdd` 技能进行红绿重构。
- 需要管理 Issue/Ticket 并进行标准化分类时，配置 `/triage` 技能使用特定标签。

**需要注意的坑**：
- 更新繁琐：部分 Agent（如 Gemini CLI）不支持自动更新，每次更新需手动重新运行安装命令。
- 初始化成本：每个新仓库都需要运行一次 `/setup-matt-pocock-skills` 进行配置，不能全局直接生效。
- 依赖 Agent 支持：仅适用于 Claude Code、Copilot 等支持插件系统的 Agent，普通 LLM 无法直接使用。
- 心智负担：需要用户改变习惯，必须先执行 `/grill` 等步骤，不能直接扔给 AI 就不管了。
